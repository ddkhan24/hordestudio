# Horde Studio 18.1.1

Virtual Human reply recovery and Windows compatibility patch.

## Replies no longer stall at “Attention is available”

- Distinguish a character becoming ready from the text model actually starting.
- Surface when automatic replies are off instead of leaving the chat on an attention message indefinitely.
- Add a one-click **Enable replies · may use credits** recovery action. The saved user message continues once; it is not sent again.
- Add an Automatic replies control to the Human Workspace Connections page, with explicit credit and saved-message behavior.
- Surface local reply-worker failures in chat, life status and runtime controls.

## Safer failures

- Record prompt-size and provider-configuration failures as durable, visible reply failures.
- State when a failure happened before submission so creators know no provider request was made.
- Deduplicate identical preflight failures so the live timeline does not churn while waiting for a fix.
- Keep the message and life state available for recovery.

## Platform reliability

- Preserve the Windows locale compatibility repair for Virtual Human dialogue workers.
- Poll only sanitized service error fields needed by the interface rather than retaining the full service status payload.

## Verification

- 48 dialogue, provider and prompt-context tests pass.
- The real local service reproduces and recovers the exact attention-ready/automatic-replies-off state with one saved user turn and one assistant reply.
- The complex creation and gameplay browser scenario passes 23/23 checks.
- The 100-day life simulation passes 10/10 checks with no findings.
- Release tests use fixture providers and do not submit paid generation.
